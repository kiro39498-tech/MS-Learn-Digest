# MS Learn Digest

> A production-grade **Microsoft Learn intelligence platform** that delivers AI-curated learning updates, structured learning tracks, and collaborative team newsletters — directly to your inbox.

---

## Overview

MS Learn Digest solves a real problem: the Microsoft Learn catalog has thousands of modules and learning paths, updated constantly. Nobody has time to monitor it manually.

The platform:
- Syncs the Microsoft Learn Catalog API daily and caches metadata
- Lets users subscribe to topic areas (Azure, Fabric, Security, GitHub, etc.)
- Generates personalised digests using **Groq (Llama 3.3 70B)** — once per unique topic+content combination, never repeatedly
- Delivers AI-generated **structured learning lessons** via a phased curriculum engine
- Supports **team newsletters** for engineering and IT teams
- Runs on a **FastAPI + PostgreSQL + APScheduler** backend with a **React + Vite** frontend

---

## Features

| Feature | Description |
|---|---|
| **Google OAuth Login** | Sign in with Google — standard OAuth 2.0 PKCE flow |
| **Email Magic-Link Login** | Passwordless login — a single-use link sent to your inbox |
| **Topic Subscriptions** | Hierarchical topic tree (Azure → Networking, Compute, Security…) with card-based selector |
| **Personalised Digests** | AI-written newsletters covering new/updated MS Learn content matching your topics |
| **Digest Scheduling** | Daily, weekly, bi-weekly, or monthly — delivered at your chosen time in your timezone |
| **Learning Tracks** | Structured curriculum (e.g. Azure Administrator: 7 phases, 75 lessons) from Beginner to Expert |
| **Phase Selection** | Subscribe to a full track or choose specific phases (e.g. only Networking + Security) |
| **AI Lesson Generation** | Each lesson generated by Groq — deep technical explanations, Mermaid diagrams, quizzes, exercises |
| **Lesson Caching** | Generated lessons are cached in `generated_lessons` — one Groq call per module, shared across all users |
| **Streak Tracking** | Consecutive learning day counter per track |
| **Team Newsletters** | Create a team, invite members by email, configure a shared newsletter schedule |
| **Admin Testing Panel** | SMTP check, test digest send, catalog sync trigger, team testing |
| **Self-Healing Onboarding** | `is_onboarded` flag auto-repaired if user has subscriptions |

## Architecture

```
Browser (React/Vite)
     │  JWT Bearer
     ▼
FastAPI Backend (Python 3.12)
     ├── /api/auth      Google OAuth + Email Magic-Link → JWT
     ├── /api/topics    Hierarchical topic tree + subscriptions
     ├── /api/digests   Digest history
     ├── /api/learning  Learning tracks, phases, progress
     ├── /api/teams     Team + newsletter management
     └── /api/admin     Testing, catalog sync, diagnostics

APScheduler (in-process)
     ├── catalog_sync_job     — daily at 02:00 UTC (configurable)
     ├── digest_dispatch_job  — every 15 minutes
     └── learning_dispatch_job — every 30 minutes

PostgreSQL (via SQLAlchemy + Alembic)
Groq API (Llama 3.3 70B) — digest generation + lesson generation
SMTP (Gmail TLS) — all outbound email
MS Learn Catalog API — content metadata source
DuckDuckGo + BeautifulSoup — resource discovery for lessons
```

## Environment Variables

Copy `.env.example` to `.env` and fill in your values:

```env
# Database
DATABASE_URL=postgresql://user:password@localhost:5432/mslearndigest

# SMTP — Gmail with App Password
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
SMTP_EMAIL=your-email@gmail.com
SMTP_PASSWORD=your-16-char-app-password

# Google OAuth
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-secret
GOOGLE_REDIRECT_URI=http://localhost:8000/auth/google/callback
FRONTEND_URL=http://localhost:5173

# Groq AI
GROQ_API_KEY=gsk_...
GROQ_MODEL=llama-3.3-70b-versatile

# JWT
JWT_SECRET_KEY=change-this-to-a-long-random-string
JWT_ALGORITHM=HS256
JWT_EXPIRATION_HOURS=72

# App
APP_NAME=MS Learn Digest
APP_ENV=development
LOG_LEVEL=INFO
```

Frontend `.env` (in `frontend/`):
```env
VITE_API_URL=http://localhost:8000
VITE_GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

## Setup Instructions

### 1. Database

```bash
# Create database
createdb mslearndigest

# Set DATABASE_URL in .env, then:
cd backend
pip install -r requirements.txt
alembic upgrade head
```

### 2. Backend

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

On first start, the scheduler automatically:
- Seeds all system topics (Azure, Fabric, Security, GitHub, etc.)
- Seeds the learning curriculum (topics + phased modules)

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Vite starts at `http://localhost:5173`.

### 4. Initial Catalog Sync

After starting the backend, trigger the first catalog sync manually:

```bash
curl -X POST http://localhost:8000/api/admin/catalog-sync
```

This fetches ~10,000+ modules and learning paths from the MS Learn Catalog API and caches metadata in `catalog_cache`. This is required before any digests can be generated.

## Google OAuth Setup

1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Create OAuth 2.0 credentials → Web application
3. Add Authorized redirect URI: `http://localhost:8000/auth/google/callback`
4. Copy Client ID and Secret to `.env` and `frontend/.env`

---

## Groq Setup

1. Register at [console.groq.com](https://console.groq.com)
2. Create an API key
3. Set `GROQ_API_KEY` in `.env`
4. Default model: `llama-3.3-70b-versatile` (configurable via `GROQ_MODEL`)

---

## Gmail SMTP Setup

1. Enable 2-Factor Authentication on your Google account
2. Go to [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
3. Generate an App Password for "Mail"
4. Use the 16-character app password as `SMTP_PASSWORD`

## Troubleshooting

| Symptom | Fix |
|---|---|
| No digests sent | Run `POST /api/admin/catalog-sync` first — `catalog_cache` must have data |
| SMTP auth failed | Use Gmail App Password (not account password). See [App Passwords](https://myaccount.google.com/apppasswords) |
| Google login fails | Check `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and redirect URI in Google Console |
| Learning topics empty | Call `POST /api/learning/seed` or restart backend (seeds on startup) |
| `alembic upgrade head` fails | Check `DATABASE_URL` in `.env` matches running PostgreSQL instance |

Full guide: `docs/Troubleshooting.md`
